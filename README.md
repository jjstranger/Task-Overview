# 个人项目看板 — 使用说明（M4）

## 版本追踪（代码回退看这里）

这个工程用 **git** 做版本追踪，仓库就在工程目录里（`.git`，纯本地，没推远端）。
**数据**（你的项目内容）另有快照机制，在设置面板里，两码事：

| | 管什么 | 在哪看 | 能回到多早 |
|---|---|---|---|
| **git** | 程序代码 | 本节的命令 | 从第一次提交到现在，任意一版 |
| **快照** | 你的项目数据（合同、环节…） | 设置 →「数据快照」 | 最近 10 份 |

日常用 `tools\ver.py` 就行，不用记 git 命令：

```
python tools\ver.py                  # 看现在有没有没提交的改动
python tools\ver.py log 20           # 看最近 20 次提交
python tools\ver.py save "这轮改了什么"  # 提交当前改动（自动附上改了哪些文件）
python tools\ver.py tag v1.1 "里程碑说明" # 给当前版本打个标签
python tools\ver.py tags             # 列出所有里程碑
python tools\ver.py show v1.0        # 看某一版改了什么
python tools\ver.py diff v1.0        # 跟某一版比现在的差异
python tools\ver.py back v1.0        # 回到某一版（会先自动存档当前状态）
python tools\ver.py undo             # 撤销上一次提交（改动保留）
```

**关于 `back`（回退）**：它**不改写历史**，而是把目标版本的文件内容取回来覆盖工作区，
并且**先把当前状态自动提交**一份。所以回错了用 `back <那个存档的 hash>` 再倒回来，
不存在"回退之后找不回来"这种事。

**什么东西不进版本库**（见 `.gitignore`）：`dist/`（出包产物，43 MB，可再生）、
`data/`（WebView2 缓存与日志，是本机运行状态）、冒烟中间文件。
所以提交很轻（整个 `.git` 现在还不到 400 KB）。

**约定**：每次功能改完、回归跑绿了，就 `save` 一版；出包前确认一下
`python tools\ver.py` 是干净的 —— 这样"某个 exe 对应哪版代码"永远对得上。

## 启动

**方式一（推荐给别人用）**：`dist\天在看\天在看.exe` —— 打包好的单目录 exe，目标机器不需要装 Python。
第一次启动会在 **exe 同级的 `data\`** 建 WebView2 用户数据目录和日志。整个 `天在看` 文件夹一起拷走即可，别只拷 exe。

**方式二（开发机）**：双击 `run.bat`（无控制台窗口）。

排查问题请用 **`run_debug.bat`**：保留控制台窗口，并把实时输出写进 `data\launch.log`。
打包后的 exe 出问题看 **`exe 同级\data\launch_error.log`** 和 `boot.log`。

## 打包 exe

```
python tools\build_exe.py              # onedir：dist\天在看\天在看.exe（默认）
python tools\build_exe.py --onefile    # 单文件：dist\天在看.exe
python tools\build_exe.py --console    # 保留控制台窗口，排查打包问题用
python tools\build_exe.py --outdir X   # 出到别的目录做对照构建
```

- **默认 onedir**：pywebview 靠 pythonnet 加载 `webview/lib` 里的 .NET 程序集，DLL 躺在 exe 旁边最稳；
  onefile 每次启动都要解包几十 MB 到临时目录，启动慢且更容易出问题
- 优先用 ASCII 名 `Task-Overview` 构建、出包后再落位成正式名（取自 `app/version.py` 的 `EXE_STEM`）
- **打包不删旧产物**：已存在的那份改名成 `.prev-<时间戳>` 让位，确认新版没问题后自己清理

## 打 zip 给别人

```
python tools\pack_zip.py                      # → dist\天在看_v1.1.zip
python tools\pack_zip.py --outdir D:\share    # 换个地方放
```

解压出来是**一个文件夹**（`天在看\`），连文件夹整个拷到目标机器即可，别只拷 exe。
目标机器不用装 Python：首次运行会在 **exe 同级**自己建 `data\`（WebView2 数据目录、日志）。

⚠ 为什么不顺手打包整个 `dist\` —— 里面混着本机运行状态，打过去会连累别人：
`data\webview2` 是浏览器 profile 缓存（还留着本机被强杀过的痕迹，残留会让第一台解压的机器
起不来），`data\config.json` 记着上次读哪个库，`tests\smoke_note.txt` 是冒烟报告。
所以 `pack_zip.py` 按**白名单**收集（exe + `_internal\`），以后冒烟又落了新东西也不会静默跟着进包。

打包完**一定要跑一次** exe 冒烟 —— 打包出问题几乎都不是逻辑错，而是资源没带进去 / 路径算错，
这两类在源码模式下永远测不出来：

```
python tests\_diag\smoke_exe.py            # 默认 persist 档（库里有 nosandbox=1）
python tests\_diag\smoke_exe.py fallback   # 给环境变量 BOARD_NOSANDBOX=1
python tests\_diag\smoke_exe.py sandbox    # 强制开沙箱跑一次（这台机器上多半会停在半路）
```

它会断言（**117 项**）：exe 起得来、`web/` 打进去了（默认折叠态主页 5 行 / 热力图 371 格）、三个页签都在、
财务页切得过去、**6 张卡分两行三张且默认看本年份**、
**财务筛选栏是年份下拉 + 导出下拉菜单、币种组已撤**、
**项目页有「筛选 ▾」、菜单首项是「隐藏归档项目」、数据带 `archived` 字段**（新加的前后端都进了包）、
外包支出与实际收入口径对得上、制作人字段可用、
**外包商名录（个人 / 团队）可用、外包支出必填外包商、外包商汇总口径对得上**、
**结款走的是「核销待收」：合同额一条不动、凭空多出一条核销、待收归零**、
**子环节序列模板 `WD####(12-20)` 解析得出 9 个**（改动在 `node_spec.py` 里，这条专门盯着"包里的后端还是旧的"）、
M4 的拖拽与快照可用、进度条按状态算、批量录入解析器打进包了，
以及 **`frozen=true` 且 `data\` 落在 exe 同级**（不是解包临时目录）。

> ⚠ **红了几条先别急着改代码**：exe 冒烟和 GUI 冒烟一样有偶发抖动（实测：同一份产物
> 一遍 3 条红、清掉上一次冒烟留下的 `dist\天在看\data` / `tests` 再跑就全绿）。
> 顺序永远是 —— 先 `tools\nasfs.py` 清残留、再重跑一遍，还红才当它是真的。

> **沙箱那档为什么会挂**：这台机器的 WebView2 渲染进程沙箱时好时坏，沙箱起不来时症状是
> "页面加载了、桥也通了，但 JS 过了一会儿就没动静"，自检报告停在半路（`stages` 只有前几项），
> 特别像应用自己的 bug。所以默认走降级档；`sandbox` 档留着专门复现这个环境问题。

## 界面

顶栏左侧是**三个页面页签**：

- **项目** — 树形看板（商业 / 个人是树里的两个分组，不再做成筛选按钮）
- **活跃** — 热力图，53×7 小绿格
- **财务** — 汇总卡片 + 四组数据（**标签页**：项目款项 / 客户汇总 / 外包商汇总 / 应收账龄）

右侧按钮依次是：`置顶` `打卡` `设置` `＋ 项目`。

快捷键：`Ctrl+1` 项目 · `Ctrl+2` 活跃 · `Ctrl+3` 财务 · `Ctrl+N` 新建项目 · `Ctrl+D` 打卡 · `Ctrl+,` 设置 · `Esc` 关弹窗。

### 新建项目

名称 + 分类 + 项目根目录（**「浏览」直接选文件夹**）+ 截止日期 + 结款日期 + 客户 + 合同额 / 首款。

- **客户是个可输入的下拉框**：候选里列出已有客户，也可以直接敲一个新名字 —— 库里没有就自动建客户，不用先跑去财务页建。
- **合同额 / 首款留空就是不记钱**，之后在财务页随时补。
- **结款日期**：跟客户约定的收款日，可以留空。它**只影响已交付项目的「结款逾期 N 天」**
  （见下面「停滞与到期告警」）；没填就不报，不会拿别的日期替你推算。

### 项目设置

项目行尾 `⋯` → **「项目设置…」**，一页改完名称 / 分类 / 客户 / **制作人** / 截止日期 / 结款日期 / 项目根目录
（版面跟新建项目一致），点「保存」一次性生效。

- **制作人是个可输入的下拉框**（跟客户一个待遇）：候选来自财务页那张**外包商名录**，
  也可以直接敲一个新名字 —— 名录里没有就自动建一条。留空 = 未分配。
- 这四个入口原本散在 `⋯` 菜单里（「编辑截止日期」「改客户」「改分类」）或双击标题，一次只能改一样；
  2026-10-13 起全部收进这一页，`⋯` 里那三条已撤掉（环节的截止日期仍在菜单里 —— 环节没有设置页）。
- 只把**真的改了**的字段下发，所以「打开看一眼再保存」不会动活跃度时间戳。
- 金额不在这里：那是「登记款项」的事，两处都能改必然出现「哪边为准」。

### 批量新增子环节

行尾 `⋯` →「新增子环节」，填写框里一行可以写一整个批次：

```
s001,s003A,s006-009    →  s001  s003A  s006  s007  s008  s009
EP01_S001_C001-C005    →  EP01_S001_C001 … EP01_S001_C005
WD####(12-20)          →  WD0012  WD0013  …  WD0020
```

- 分隔符：**逗号 / 分号 / 顿号 / 空格 / 换行**（全角半角都认）
- **连接号**生成连续编号：两边都是「前缀 + 数字」时展开；只写数字的一边继承前缀（`s006-9`）；倒序也认（`s09-s06`）
- **序列模板**（2026-10-16 新增）：**几个 `#` 就是补零几位**，范围写在括号里 ——
  `WD####(12-20)` → WD0012…WD0020。写法细节：

  | 写法 | 结果 | 说明 |
  | --- | --- | --- |
  | `WD####(12-20)` | WD0012 … WD0020 | 4 个 `#` = 4 位 |
  | `shot##(8-10)` | shot08 shot09 shot10 | 前缀可以任意长、也可以没有 |
  | `WD####（12-20）` | 同上 | 全角括号、波浪号 `~` 都认 |
  | `WD#### ( 12 - 20 )` | 同上 | 模板里的空格**不算**分隔符 |
  | `WD####(20-12)` | WD0020 … WD0012 | 倒序也认；`(12-12)` 就建那一个 |
  | `WD##(8-105)` | WD008 … WD105 | 位数写少了会**自动加宽**，不会长短不齐 |
- 名字里本来带连接号的不会误伤：`SANTI-OneDay`、`shot-001`、`s001_alpha` 都原样保留。
  实在想强制字面量就用引号包起来：`"phase1-3"`
- 含 `#` 又带括号、但没写成完整模板（比如 `WD####(12)`）会**当场报错**并告诉你正确写法 ——
  不会悄悄建出一个叫 `WD####(12)` 的环节
- **创建前有实时预览**：把会建的名字逐个列出，已存在的划掉，所以拿不准时看一眼就行，不用记规则
- 同一批再提交一次不会产生重复 —— 已存在的同名子环节会被跳过，并告诉你跳过了几个

## 打不开怎么办（先看这个）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 双击毫无反应，也没报错 | `pythonw.exe` 静默退出，且没有地方显示堆栈 | 看 `data\launch_error.log`；或跑 `run_debug.bat` |
| 弹框说被别台机器占用 | NAS 上另一台机器正在用同一个库 | 另一台退出后等 1 分钟（心跳过期） |
| 窗口在托盘里，双击没动静 | 应用关窗口只隐藏到系统托盘，不是退出 | 托盘里点一下图标；再双击 run.bat 会自动拉起已有窗口 |
| 窗口出来了但页面空白 / 一直转 | WebView2 渲染进程沙箱被安全策略拦住，JS 桥不通 | 正常情况下会自动降级：等 15 秒左右窗口自己重启一次就好了（见下） |

单实例靠 **Windows 命名互斥量**判定（进程被强杀也会自动释放），所以崩溃后立刻双击就能重开，不需要等、也不需要手工删锁。

`.bat` 文件必须是 **GBK 编码 + CRLF 换行**：cmd.exe 按本地代码页解析批处理，UTF-8 或无 BOM 的 LF 会让中文注释变成乱码命令，直接把脚本跑挂。改动 `run.bat` 请用 `tests\_diag\_gen_bat.py` 生成，别直接手写保存。

### 沙箱起不来时的自动降级

某些机器的安全策略（或 WebView2 Runtime 本身有问题）会让渲染进程的沙箱起不来，症状是**窗口弹出来了、但页面永远不加载**。看门狗线程会在 15 秒内等前端报到（`api.boot_ok`），没等到就：

1. 把 `nosandbox=1` 写进数据库
2. 释放锁和互斥量，带 `--no-sandbox` 重启自己
3. 重启后页面正常，**并且记住这个状态**——之后每次启动直接走兼容模式，不会再等 15 秒

连降级都失败时才会弹错误框提示你去修复 WebView2 Runtime。

想手动开关：设置 → **兼容模式**（改完要重启）。只有在页面起不来的时候才需要打开；页面正常的话关掉更安全。

## M1 已实现

- 主页树形看板：商业 / 个人分组 → 项目 → 环节 → 子任务，**无限层级 + 折叠持久化**
  - **打开时默认只展开「商业 / 个人」两个分组行，其下的项目一律收起**——一眼看到有哪些项目；要看细节点行首的 ▶（状态写库，重开保持原样）
  - 早先那三个「全部展开 / 全部折叠 / 只看项目」按钮已按用户要求撤掉：默认状态本身就对，留着按钮反而是第二套折叠语义
- 状态手动更改（点状态徽章弹出菜单）、双击标题改名、叶子节点点圆点勾通过
  - **环节（镜头）制作状态** 10 态：`待开始 / 等上游 / 制作中 / 暂停 / 中止 / 已提交 / 反馈 / 可优化 / 通过 / 交付`
    （主线 `待开始 → 等上游 → 制作中 → 已提交 → 反馈 → 可优化 → 通过 → 交付`，旁支 `暂停` `中止`）
    - 2026-09-30 改版：「取消」改叫「中止」；新增 **「可优化」**——还想改的活儿，既不算
      交付量也不算收工，所以两边都不占
  - **项目状态**另有独立一套 7 态：`筹备 / 进行中 / 阻塞 / 已交付 / 已结款 / 归档 / 中止`
    （同批次改版：撤掉「待交付」退向「进行中」，「搁置」改叫「中止」）
  - 环节里 `通过 / 交付 / 中止`、项目里 `已交付 / 已结款 / 归档 / 中止` 属于收工态，
    不再进到期提醒；**不算停滞**的项目状态是 `筹备 / 已交付 / 已结款 / 归档`
    —— 筹备还没开工、已交付制作已经结束，两个都不该报「停滞」；
    **老库里的旧状态词开库时自动迁移**（环节用环节的迁移表、
    项目用项目的，两边的词不能串）
- 行尾 ⋯：**项目设置…** / 新增子环节 / 备注 / **制作人** / 登记款项 / 今日必做 / 归档 / 删除
  （环节那一行没有「项目设置」，「编辑截止日期」就留在它的 ⋯ 里）
  - 环节的**「编辑截止日期」是个日历控件**（2026-10-16 起）：弹窗里一个原生日期框，
    点右边图标选日期，不用再手打 `YYYY-MM-DD`；多选批量改截止日期走的也是同一个弹窗
- **项目页筛选菜单**（工具栏「筛选 ▾」，选择记在本地，重开保持）：
  - **隐藏归档项目**（默认就是勾上的）：**归档有两条路**，两条都认 ——
    ① 行尾 ⋯ 里的「归档」动作（写 `archived` 字段）；② 直接把项目状态点成「归档」。
    隐藏时后端**根本不发往前端**，所以归档是真的「收进抽屉」；关掉开关才会要一次，
    归档行会压暗并挂一个虚框「已归档」徽章，行菜单同时变成「取消归档」（状态归档的会改回「已交付」），
    否则收进去就再也捞不回来了
    - 开关是**反着写**的：默认态（隐藏归档）按钮上不挂字样，只有关掉隐藏、真的把归档拉出来看时，
      按钮才变成「筛选：含归档 ▾」
    - 筛「归档」这个状态时会自动放开隐藏 —— 不然点了「归档」出来一棵空树，像是项目丢了
  - **按项目状态筛**：全部状态 / 筹备 / 进行中 / 阻塞 / 已交付 / 已结款 / 归档 / 中止
    （纯展示层过滤，不走一次跨桥）。按钮上会写着当前筛的是什么，筛空了给一句说明
  - 分组行的**进度条与比例始终按整个分组算**（它是「这个分类整体做到哪了」），只有条数显示「筛后（共 N）」
- **制作人**：项目、环节都能填一个「谁在做」，挨着备注显示成 `制作人 老王`，行菜单里改；留空就清除。
  - 制作人是**外包商名录**里的一条（见下面「外包商 / 制作人名录」）——**存的是 id，不是名字**：
    改个名，筛选条件、行上显示、挂靠关系全都跟着走，不会失配。
  - 环节层还能**多选批量**改：勾几条 → 批量条「改制作人 ▾」；菜单里是名录 + 「未分配（清空）」+「新建一个外包商…」。
- **进度条按状态算**：父行显示 `已完成叶子数 / 总叶子数` + 进度条，叶子走到 `通过` 或 `交付` 就算完成
  - 早先进度只认叶子上的勾选框，用户把环节改成「通过」后进度**恒为 0**——已改成读数据时按状态派生，勾选框只是最顺手的那个动作
- 目录入口：打开▾ 列出项目 / 环节关联的目录（explorer 打开），可现场添加

### 结款（核销待收）

项目收尾时点一下，**把收不齐的待收核销掉，让待收归零**。入口：财务页「＋ 记一笔」，
类型选**到账**时，弹窗底部会露出**「结款（核销待收）」**按钮。

**它不改合同额，也不删任何记录。** 这是 2026-10-16 改的口径 —— 旧做法是把合同额
改成实收、把多余的合同额记录合并删除，那样会把**损失从账面上抹掉**：

```
合同 150,000  已收 120,000  待收 30,000  收款率 80%
   ↓ 旧做法：合同额改成 120,000，损失 3 万无声消失，收款率变成 100%
   ↓ 现在的做法：多一条「核销 30,000」，合同额仍是 150,000，待收 0，收款率仍是 80%
```

- **结算方式**：结款让「核销」这一项等于 `合同额 − 已收`，由**一条备注写着「结款核销」**的记录承载
  - 之前核销过 → 改它那条的金额（id 不变）；一条都没有 → 新建一条
  - 后来又收到钱 → 再点一次结款，核销额会**自动调小**；收齐了就**自动作废**（账自己回来）
- **幂等**：已经结清了就直说「已经结清了，没有待收要核销」，不改任何东西（连点两次不会多出记录）
- **一笔「已收」都没有时拒绝执行** —— 那等于把整份合同一次性核销掉，不是"结款"该干的事
- **你自己手记的核销不会被碰**：比如先手记一条「银行手续费 100」，再点结款，
  它只补差额（`应该核销的总额 − 手记的`），备注原样保留
- **撤销**：把那笔核销记录改成「作废」或删掉，待收就回来了 —— 比"改合同额"好撤销得多
- **合同额真的变了**（签了补充协议确认就是 12 万）走另一条路：去改 / 加**合同额记录**本身，
  不要用结款。这也是这轮改动把两件事分开的意义

### 外包商 / 制作人名录

一条外包商 = **一个干活的人 / 一个团队**，它同时是两个角色的主体：

| 挂在哪 | 存哪 | 谁在用 |
|---|---|---|
| 项目 / 环节的**制作人** | `projects.artist_id` / `nodes.artist_id` | 项目树的行上显示、筛选、批量改 |
| 财务的**外包支出** | `finance.vendor_id` | 外包商汇总、导出 |

**这就是"打通"的意思**：同一个人既是干活的那个，也是收钱的那个 —— 所以只维护一份名录。

- **字段刻意精简**：名称 / 类型（**个人 / 团队**两档）/ 联系方式 / 备注。
  比客户那套 7 字段少，因为它是"给钱的对象"，不是"要维护关系的甲方"
- **入口**：财务页右上角「外包商」按钮（跟「客户」并排）。列表每行尾 `⋯` → 编辑 / 删除
  - 列表里**「挂靠」那列只显示挂靠项目数**（2026-10-16 起精简，原来是「N 项目 · M 环节 · K 笔款」）。
    显示精简了**删除保护没松**：有环节或款项挂着照样删不掉，点 ⋯ → 删除时后端会把原因说清楚
- **强关联（存 id）**：改个名字，筛选条件、行上显示、挂靠关系全都跟着走。
  这也是为什么筛选按 id 比、不按名字比 —— 按名字比的话，改一次名所有筛选条件就静默失配了
- **删除是有保护的**，会盯**三处**牵连并说清数量：
  还有 `N 个项目` / `N 个环节` 的制作人是他，或还有 `N 笔外包支出` 记在他名下，就先不让删 ——
  只报一句「删除失败」用户没法行动
- **清空挂靠 ≠ 删条目**：把项目的制作人留空只是解除关联，名录里那个人还在
- **老库自动迁移**：升级前用裸文本记的制作人（`projects.artist` / `nodes.artist`）会在开库时
  **一次性**转成名录条目并回填 id（同名合并、区分大小写与首尾空白；幂等，只跑一次）。
  裸文本那两列**留着但不读** —— 显示名一律从名录里取
- **升级提醒**：升级前记下的老「外包支出」没有外包商，**编辑它时会被要求补填**（新记的必须填）
- **记账入口有三处**，都是同一套口径
  1. **建项目时就填**：顶栏「＋ 项目」弹窗里可一起填 **客户 / 合同额（含税率）/ 首款到账（含日期）**，留空就是只建项目
     - 合同额落成状态「有效」的合同记录，首款落成状态「已收」的到账记录（备注写「首款」）
     - 金额填错了**整个建项目动作会被拒绝**，不会留下一个"以为记上了其实没记"的空项目
  2. **项目行上顺手记**：树里任意项目行尾 ⋯ → **登记款项**，弹窗已预选好这个项目
  3. **财务页**：右上角「＋ 记一笔」，或展开项目行点某笔流水的 ⋯ 改 / 删

## 验证页面状态（排障用）

只看"窗口有没有出来"会漏掉一大类失败（比如数据没加载、JS 报错）。`--smoke` 会让页面自己把各页面的渲染统计**从 JS→Python 这条通道**回传，写进 `tests\smoke_note.txt` 后退出：

```
<venv>\Scripts\python.exe app\main.py --smoke --no-tray --db tests\_tmp.sqlite
type tests\smoke_note.txt
```

正常是一个 JSON：`stages` 走完 `tree/heat/fin/block/done`，`err` 和 `failed` 都是 `null`，另外带主页行数、热力图格子数、财务卡片数、账龄档数等。

用 `evaluate_js` 回读是不可靠的：它要等 window 的 `loaded` 事件，那个事件在部分环境下不触发，会报 `Main window failed to start` 或者干脆空等。**Python→JS 这条方向不能用，JS→Python 才是稳的**。

前端自检每一步都带超时（`guard`），任何一步卡住或抛错都会把 `failed` / `err` 和已走到的 `stages` 报回来，不会静默卡死。

## 已知的 pywebview 坑（开发时注意）

1. **不要给 `url` 路径拼 `?x=1` / `#x` 后缀** —— pywebview 用 `os.path.exists` 判断本地文件，带后缀会被当成远程 URL，白屏
2. **不要在 GUI 事件回调（shown/loaded）里调 `evaluate_js`** —— 会死锁，窗口标题变"未响应"；要从后台线程调（`webview.start(func)` 的 func）
3. **不要给 `Window.on_top` 属性赋值** —— 某些版本没有 setter，在 GUI 线程抛异常会中断加载流程；置顶统一走 `ctypes SetWindowPos(HWND_TOPMOST)`
4. **js_api 对象的公开属性会被序列化进 JS 桥** —— 挂 window/db 等不可序列化对象会搞挂整条桥；内部引用用下划线前缀
5. **强杀进程会污染 WebView2 用户数据目录** —— 下次启动可能报 `Main window failed to start` 或白屏；等一会儿重开或换 `WEBVIEW2_USER_DATA_FOLDER` 即可恢复
6. **SQLite 必须 `check_same_thread=False` 并加锁** —— pywebview 的 JS 桥跑在内置 HTTP 服务线程，调度器又是另一个线程，默认设置会报 "SQLite objects created in a thread can only be used in that same thread"，表现为窗口能开但数据是空的
7. **`.bat` 必须 GBK + CRLF** —— Write 工具默认产出 UTF-8 + LF，cmd.exe 按 GBK 解析，中文注释会变成一堆非法命令（报错形如 `'夎捣' 不是内部或外部命令`），最后是"双击没反应"。生成 bat 用 Python 显式指定 `encoding='gbk', newline='\r\n'`
8. **`pythonw.exe` 挂了是彻底没声音的** —— 没有控制台就没有 traceback。入口要单独垫一层（`app/_boot.py`）：`try: import main` → `fatal(traceback)` 写日志 + `MessageBoxW`，否则用户看到的就只有「双击没反应」四个字。甚至 import 阶段的错也要能抓到
9. **单实例判定不要用 pid/锁文件** —— 托管版 Python 会先起一个 launcher 再 exec 真正的解释器，`os.getpid()` 记录的那个可能已经退了；强杀又会留下孤儿锁让下次误判"被占用"。改用 `CreateMutexW("Local\\<app>_<dbhash>")`，内核持有句柄，进程没了就自动释放
10. **Python→JS 的 `evaluate_js` 不可靠，JS→Python 才稳** —— 前者要等 window 的 `loaded` 事件，部分环境不触发，轻则报 `Main window failed to start`，重则在桥半死时直接卡住调用方。所有探针 / 健康检查都要让前端**主动调** Python 方法（本项目用 `api.boot_ok`），不要用 `evaluate_js` 去问
11. **`evaluate_js` 不能当看门狗探针** —— 桥挂掉时它是**卡死**而不是抛异常；用它当探针会把看门狗自己一起挂住，于是永远发现不了问题。看门狗只认"前端有没有报到"
12. **跨桥的 Promise 可能既不 resolve 也不 reject** —— 桥半死（窗口在、JS 能调 Python，但回值路径断了）时就会这样。任何自检 / 冒烟都要给每一步包一层超时（`Promise.race`），否则会静默卡死，连"卡在哪一步"都拿不到
13. **`--no-sandbox` 只能靠环境变量在 `webview.start` 之前设** —— 通过 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 传，且必须在 WebView2 初始化前生效。这类降级开关一旦验证有效就**持久化到数据库**，否则每次启动都要白等一遍看门狗超时
